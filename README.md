# Calibrated, Adaptive ThinkPRM

Generative process reward models that are **calibrated**, **analyzed**, and **cheap**.

Follow-up to ThinkPRM (Khalifa et al., arXiv:2504.16828, 2025). Three parts:

- **(A) GRPO + calibration reward** instead of rejection sampling — keep *all* synthetic chains, optimize calibration directly (Brier score), not just agreement.
- **(B) Step label interference** — counterfactual experiments quantifying how an early "incorrect" judgment biases later step judgments in autoregressive verification.
- **(C) Adaptive verification cascade** — cheap verifier first, expensive ThinkPRM only when uncertain; report accuracy vs. total FLOPs Pareto frontier.

Target: arXiv preprint by early December 2026.

## Quickstart (Kaggle / cloud VM)

```bash
pip install -r requirements.txt

# 1. download + unify data (keeps ALL chains, including rejected ones)
python scripts/data/prepare_prm800k.py --out data/prm800k_unified.jsonl
python scripts/data/prepare_mathshepherd.py --out data/mathshepherd_unified.jsonl

# 2. train discriminative baseline (cheap, fits Kaggle T4)
python scripts/train/train_discprm.py --config configs/discprm_1p5b.yaml

# 3. SFT baseline (ThinkPRM-style: rejection-sampled, chosen-only)
python scripts/train/train_sft.py --config configs/sft_1p5b.yaml

# 4. GRPO with calibration reward (needs ~48GB VRAM, e.g. A6000)
python scripts/train/train_grpo.py --config configs/grpo_1p5b.yaml

# 5. evaluate: accuracy + ECE/Brier on ProcessBench
python scripts/evaluation/evaluate.py --model <path> --bench processbench
```

## Key design decisions

- **Unified data format** keeps *every* candidate completion per step with its gold label
  (`gold: 1` = correct, `0` = incorrect), plus which one the human chose. GRPO trains on all of
  them; the SFT baseline trains on chosen-only (the rejection-sampling proxy).
- **Verifier output format** (what the model must generate):
  ```
  Step 1: correct
  Step 2: correct
  Step 3: incorrect
  First error step: 3
  Final: incorrect
  Confidence: 0.82
  ```
  `rewards.py` parses this and computes `r_agree` (per-step, incorrect steps up-weighted),
  `r_localize` (first-error-step bonus), `r_cal` (−Brier on Confidence vs gold final label).
- Label mapping for PRM800K: rating `1`/`0` → correct, `-1` → incorrect, `None` → dropped.
  See `docs/DATA_NOTES.md` for verified distributions (they differ from the proposal's guess —
  the weight defaults in configs reflect the *measured* numbers).
